本文全部分数、人数、成功次数、时长和偏好分布都是模拟教学例子，不是已经采集的真人结果。 各情境相互独立，不能拼成一份研究结果，也不能导入正式数据目录。本文不修改问卷、实验分配、冻结材料或旧回答。

这份问卷能直接回答：参与者觉得哪种交互更打断、更可控、更费力、更满意，以及更愿意继续使用哪一轮的系统。要回答“更快、更准确、更稳定、少误改、少修复、成本更低”，必须结合真实任务日志和渲染证据。满意度高的人不一定完成得更准确；完成得更准确的人也不一定喜欢这一过程。

下面先给出题号和读数规则，再列出11类可遇到的回答模式。除特别讨论缺失、退出或设计偏差的部分外，每个情境都假设 20名正式参与者完成四轮、每轮4项任务，相关评分题也有20份有效回答。这只是便于看懂人数的统一分母。项目中的22是原招募目标，2个预实验加20个正式是预留容量，均不代表已到场或已完成。

1.3 人数和分母

20人每人四轮，是20个独立参与者、80条分轮问卷记录；20人每人16项任务，是320条计划任务记录。每个条件有20份分轮评分及80项任务，但不是80名或320名参与者。

一个人每个条件只做4项主任务，因此该人的成功比例只能是0/4、1/4、2/4、3/4或4/4。先求每人的条件内成功比例，再求同一人的S−N差值。相同参与者的四轮互有关联；不能当四组互不相关的人分析。

4. 开始前和结束后的题，怎样参与解释

4.1 Q1至Q3决定能否正确纳入，不是效果分数

题号 作用 20人主要情境中的要求 不允许的做法
Q1参与者编号 连接分配、问卷、实际场次与日志 20个核对过的唯一正式编号 同一人重复下载算新人；四轮算四人；依文字猜身份
Q2实验类型 区分debug、pilot、formal 纳入的20人均为formal，且与研究者记录一致 把调试或预实验补足20人；只信手填类型而不核对
Q3参加同意 本次研究参加许可 20人均明确同意，且有对应记录 没有同意仍算研究样本；旧问卷同意替代本次同意

Q3不同意时结束流程，不进入Q4至Q32。线上拒绝路径是否保存服务端记录尚未验证；不能承诺“服务器绝对不保存”。拒绝不算不满意，不能编码为1分；研究样本中也不能只因后台有一条拒绝记录就增加一人。

人数流程另报联系、到场、同意、开始、四轮完成、主动退出、技术中止，不能由问卷条数反推全部流程。例如一个独立流程模拟：20人开始，17人完成、2人退出、1人技术中止，则20＝17＋2＋1；它不再是正文假设的20个完整参与者。完整四条件比较最多17人，仍须检查各项缺失；另外3人的已完成记录按许可和事先规则保留说明，不能重填槽位、补造答案或隐去退出。

“全部结束后”是末页名称，不是退出原因问卷。当前Q28至Q32没有专门收集退出原因，研究者须用现场记录补充；不要把Q32空白猜成疲劳退出。

4.2 Q4、Q5提供背景，不证明人群需求

情境8给出了完整的20人背景分布。Q4可用于描述VR接触程度和探索体验差异，不能直接叫作“熟练度测试”；Q5用于说明原型熟悉及可能的学习效应。背景未知、记不清和不愿回答应单列，不能强行归入“新手”。

当前问卷没有直接测量年龄、性别、人格或对男性/奶龙的独立审美偏好，不能从体验分数中倒推出这些属性。也不能把少数某类使用者的回答扩展为“所有VR用户的需求”。

4.3 Q6、Q7必须满足三个条件才关联旧问卷

旧课程问卷的22条记录包含19条已知模拟回答，另3条来源尚未核实。这是旧记录的来源事实，不是本次20人的数据。模拟和来源未核实记录不能用于真人效果，也不能当作群体需求证据。

个体关联必须同时满足：旧回答已逐条确认真人来源；本人在Q6明确同意关联；Q7提供的已有匿名编号确实对应。 同意参加Q3不等于同意关联Q6；Q7非空也不等于授权仍有效。

一个独立模拟分布可以是Q6同意6人、不同意8人、没有编号/不确定4人、跳过2人，共20人。6个同意者中，4人填写已有编号、2人留空，合计6人。再假设那4条旧记录中有2条后来核实为真人、1条已知模拟、1条仍未核实，则最多关联2人。这里的“后来核实2条”只是规则演示，本文没有进行该核实，也没有新增已确认真人旧记录。

Q6撤回同意后，线上隐藏的Q7值可能仍留在前端；导出时必须重查最终许可，不能因为旧编号存在就关联。不根据文本、时间或本次新分配编号猜旧身份。

即便合法关联，旧课程问卷是不同任务和题干。旧Q5“先问/先做”的假想偏好可作探索性背景，不能当本次观察结果；旧Q6等待区间不能换算成实际平均秒数，旧Q1也不是本次VR使用经验。

6. 按现有分析计划，怎样写出可靠而不过度的结论

  1. 先确定真实样本。 核对同意、编号、场次、formal阶段、实际完成与退出。重复提交由研究者明确保留修订版本，不当作新增参与者。20不是最低导入门槛，也不是必须凑满的数字。
  2. 分别展示四项单题。 每条件给1至7的分布、有效n、无法判断n、跳过n；可补充中位数和个体配对图，不生成跨构念“总UX分”。若用均值差作为描述，保留其有序单题的解释边界，并同时给分布。
  3. 保留配对和预定比较。 主比较是每人S−N的稳定成功比例差；预定次要比较为S−A的询问/打断，以及S−E的首次成功。不要在看到结果后只挑有利指标当主结果。
  4. 显示差异大小和不确定性。 现有协议按参与者整体bootstrap，保留四条件和任务结构。客观分析器先聚合每人每条件4任务，再处理参与者配对差；不是对320条任务当独立样本抽样。若另报多项预定检验的p值，按协议作Holm校正。本文没有运行统计检验，也没有用假想人数宣布显著。
  5. 检查缺失与顺序。 报告每项完整配对人数；结合任务类型、轮次、原型经验与故障作预定或明确标为探索性的检查。样本很小时区间也不稳定，不能把一次“未显著”写成等效。
  6. 让开放题解释已观察的模式。 对齐到当轮/任务事件，保留反例；不把研究者猜测写成用户原话。Q28是回顾偏好，不替代逐轮体验与客观表现。
  7. 限定结论范围。 结论涉及实际参与者、本组外形任务、使用的模型与harness及角色素材版本；不直接外推到所有VR角色、语音交互或长期采用。

当前analyze_trials.py只自动处理客观任务指标，不自动分析问卷评分、访谈、任务类型或顺序影响。它排除非formal记录、拒绝重复试次和无效/缺失必需数值；完整参与者要求四条件各4任务且共16个不同任务。它会列出不完整者，但不替研究者完成缺失敏感性分析。能输出bootstrap区间也不代表样本充分或研究已完成。

当前import_responses.py对本地问卷文件做身份、同意、版本、重复及六页结构校验；把“无法判断”和跳过评分导出为空值，在原始记录里保留区别。问卷星导出需要先核验实际列头与编码，不能假设直接喂入本地JSON导入器即可。统一JSON中的第8个评分选项是非分数选项，不能当8分。

可直接套用的真实结果表述模板如下，方括号必须用实际数据填入：

“共有[实际人数]名正式参与者开始研究，其中[完整人数]名完成四条件。S−N稳定成功率的平均参与者内差为[数值]个百分点，[区间方法及95%区间]。满意度有[配对n]个完整配对，其中[人数]人S较高、[人数]人相同、[人数]人N较高；另有[缺失情况]。S相较A的打断感呈[实际方向]，但[努力/时间/失败的实际限制]。本结果支持[限定范围的结论]，不支持[尚未验证的更强结论]。”
