# 主持与问卷制作说明

## 内容与负担

这些题与 `../materials/protocol.md` 的四项主观指标一致，全部是**自拟单项**，不是 NASA-TLX、SUS 或其他经过验证的量表。不要对四项相加、平均或发布“总 UX 分数”。打断和努力高分表示更差，控制和满意度高分表示更好；报告时保留各自方向。

| 阶段 | 实际内容 | 填写次数 |
|---|---|---|
| 开始前 | 一次同意、两项经历、可选关联许可、条件显示的旧代码 | 一次 |
| 每个 block 后 | 四个 1–7 单项；一个可选短评 | 四次，共 16 项评分 |
| 结束时 | 一项 block 偏好；四项可选短答 | 一次 |

目标问卷负担约 6–9 分钟只是排程估计，尚未测得。预实验记录实际填写时间与不理解之处；可选短答不必逐项补访谈，也不要求每一格都写字。若全部试次均到 120 秒上限，仅 16 项任务已需要 32 分钟，另外还有操作训练、三个状态探针、问卷和休息。原 45 分钟预约并不保证足够；两位预实验后确定是否需要 50–60 分钟的正式时段，不能在正式收集中途随条件删题或压缩回答时间。

## 主持流程

1. 22 位旧问卷受访者中预先确定 `PILOT01`、`PILOT02`，其余 `P001`–`P020`；不按原澄清偏好或实验表现选择正式样本。预实验与正式数据分开。
2. 简短介绍：“We are studying how people make appearance changes to a virtual character. You will try four blocks. We are interested in what works and what does not.” 不说哪个策略是团队提出或预期较好的策略。
3. 开始前补充真实的研究联系人、数据访问范围、保存位置、保存期限和撤回方式；这些信息目前没有在项目中确定，因此问卷没有捏造期限或伦理审批。按课程实际要求说明并冻结，不影响当前开发和原型试运行。
4. 展示同意说明：新增任务/模型日志、场景截图与问卷是本次采集；旧问卷参加不自动等于同意。不同意时结束，不保存其回答。不要把自愿参加与成绩、同学关系或合作资格挂钩。
5. 研究者输入 `participant_id` 和参与者整场一致的 `study_session_id`（问卷仍以字段名 `session_id` 保存）；不要填写每个 block 新建的后端 session_id。参与者看到 block 1–4；研究条件由另存的冻结分配表对应。不要让参与者填写 E/A/N/S。
6. 每 block 完成后暂停任务，填写同一份 block 表，顺序与选项不随机化。没出现系统提问时，打断项按实际“没有被提问打断”选 1；无法判断可选择独立选项或跳过，其含义不能当成 4 分。其他指标也允许跳过。
7. 结束表先让参与者自行填写。可用中性 block 编号帮助回忆，不给 block 加“快”“智能”“选择性”等描述。如果只完成部分 block，不强迫进行四者偏好比较，记录中止与可用的 block 表。
8. 如做追问，围绕具体事件：“What happened?”“What did you expect?” 不要求参与者赞同系统，也不把研究者的解释写成原话。未经另行告知与同意，不采集人像、声音或桌面无关内容。
9. 每人结束后，核对 pre 1 份、block 最多 4 份、exit 最多 1 份以及对应日志；退出/跳过保留原因和实际分母，不补造回答。

## 与旧问卷的关系

旧问卷未必有可关联匿名代码。目前仅读到了英文修订稿与研究者说明，未核实实际发放版或 22 人逐条回答。如果参与者既允许关联又能提供**已有的匿名代码**，且研究者确实能在旧导出文件中找到同一代码，才建立对照。不能用本次新分配的 P001 反推旧问卷、不能根据文本风格或提交时间猜测身份。旧代码放在限制访问的关联表，不发送给 DeepSeek、不写进模型日志；问卷没有收集姓名/电话/邮箱。

若没有旧代码或不同意关联，旧问卷仅用群体层面的需求背景；仍可正常参加全部实验。这一批是同样 22 人的后续研究，不是又增加 22 位独立参与者。旧 Q5 的假想偏好不能当作本次满意度或成功率的前测。

## 在问卷星中制作三个草稿

此处是可执行的制作说明，不声称当前账号或具体按钮已被验证。导入文本的标题、题型标记和题干说明在不同编辑器中可能需要调整；应逐项检查预览结果。

1. 使用研究者已登录账号创建**三个新的问卷草稿**，分别命名 `Character Appearance Study — Before the Session`、`— After a Block`、`— At the End`。不要覆盖旧的需求问卷。
2. 在“文本导入”或同类编辑器导入对应 `wjx_*_import.txt`。编号题中 `[单选题]` / `[填空题]` 是题型提示，导入后检查它们未出现在参与者题干；说明文字应放到题目描述区，而非被误识别为选项。
3. 三表头部 `Study ID`、`Session code` 设为必填短文本。ID 只接受 `P001`–`P020` 和 `PILOT01`–`PILOT02`；session 允许英文字母、数字、下划线、连字符。平台不能配置完整校验时，现场核对并在导入阶段检查。
4. Pre 的同意题设为必答；选择不同意立即结束。只有同意后显示后续背景项。其余背景题可跳过。旧代码题仅在关联题选 “Yes, using a code I can provide” 时显示；允许同意关联却没有输入代码，此时不执行关联。
5. Block 的 block 1–4 题设为必答，其余题可跳过。四个评分使用**单选题**，依次保留 1–7 和第八个 “Cannot judge / prefer not to answer”。不要把第八项设为 8 分，不给任何项预选。独立单选题比手机/头显旁的小矩阵更容易阅读。
6. Exit 的偏好题是名义选择，Block 1–4、No preference、None、Cannot judge 必须保持不同编码；四个短答均可选。不能把其编号当作有序满意度。
7. 关闭收集姓名、邮箱、手机号等不必要功能，避免公开原始回答。若平台不可避免保留技术日志，应在实际告知中说明，不能承诺绝对匿名。自动问卷答案不发送给 DeepSeek。
8. **Block 表必须允许同一参与者在同一设备提交四次。**不能启用“每设备/IP/账号只能提交一次”的全局限制；用 `(session_id, block)` 检查重复。也不要将实际采集设置成限制 22 次总提交——正式 block 表计划最多 80 次，预实验最多 8 次，三表须分辨阶段。
9. 在预览中走过同意/不同意、关联 yes/no、无法判断、空可选题与四次 block 的路径；预览测试不进入真实结果。若平台会保存预览测试，请标记测试并清理，不能填入 P001 等正式编号冒充数据。
10. 记录问卷平台、草稿/发布 ID、版本与设置。用户当前授权制作问卷；本材料没有向任何人发送问卷链接，也没有发布外部问卷。待正式链接建立后再与实验应用的中性 block 导航连通。

## 导出、编码与分析

本地 JSON 保留 `answer_status`，区分 `answered`、`skipped`、`not_shown`、`cannot_judge`。问卷星导出也需对应这些含义；不要把空白转成 0，不把无法判断转成量尺中点。评分字段与现有 CSV 精确匹配：`interruption_1to7, control_1to7, effort_1to7, satisfaction_1to7`。

用冻结的 `participant_schedule.csv` 将正式 participant/block 映射到 condition。以每人四个 block 做配对描述与差值；预先指定的 S–A 打断差异单列，其余探索性结果注明。可展示各题分布、有效人数与参与者内区间；不把 80 个 block 当作 80 名独立参与者。问卷主观结果与实际成功、询问数、修复、等待和延迟分开报告。

本地导入示例（输入为实际回答文件，输出目录应是私有数据目录）：

```bash
python3 Docs/AppearanceExperiment/Study/survey/import_responses.py \
  --input-dir /path/to/actual/downloads \
  --schedule Docs/AppearanceExperiment/Study/materials/participant_schedule.csv \
  --out-dir /path/to/private/analysis
```

脚本只处理本地 HTML 的版本化 JSON，问卷星列名需导出后另做可审计映射。实际回答、关联表和会话日志不要提交至公开仓库。
