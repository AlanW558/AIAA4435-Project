# 主持与问卷制作说明

## 内容与负担

这些题与 `../materials/protocol.md` 的四项主观指标一致，全部是自拟单题指标，未经量表验证。它们不属于 NASA-TLX、SUS 等量表。不要对四项相加、平均或发布“总 UX 分数”。打断和努力高分表示更差，控制和满意度高分表示更好；报告时保留各自方向。

| 阶段 | 实际内容 | 填写次数 |
|---|---|---|
| 开始前 | 一次同意、两项经历、可选关联许可、条件显示的旧代码 | 一次 |
| 每轮结束后 | 四道 1 至 7 分的评分题；一个可选短评 | 四次，共 16 项评分 |
| 结束时 | 一项轮次偏好；四项可选短答 | 一次 |

目标问卷负担约 6 至 9 分钟只是排程估计，尚未测得。预实验记录实际填写时间与不理解之处；可选短答不必逐项补访谈，也不要求每一格都写字。若全部试次均到 120 秒上限，仅 16 项任务已需要 32 分钟，另外还有操作训练、三个状态探针、问卷和休息。原 45 分钟预约并不保证足够；两位预实验后确定是否需要 50 至 60 分钟的正式时段，不能在正式收集中途随条件删题或压缩回答时间。

## 主持流程

1. 原先目标为22人，用户已说明实际到场可能更少。预留 `PILOT01`、`PILOT02` 和正式 `P001` 至 `P020` 槽位，不要求填满。尚未分配编号者按 `../materials/recruitment_order.csv` 的固定顺序领取正式槽位；不按旧问卷偏好或实验表现选择，预实验与正式数据分开。
2. 简短介绍：“我们想了解大家如何修改虚拟角色的外形。你会完成四轮任务，请按实际体验告诉我们哪些地方好用，哪些地方不好用。” 不说哪个策略是团队提出或预期较好的策略。
3. 开始前补充真实的研究联系人、数据访问范围、保存位置、保存期限和撤回方式；这些信息目前没有在项目中确定，因此问卷没有捏造期限或伦理审批。按课程实际要求说明并冻结，不影响当前开发和原型试运行。
4. 展示同意说明：任务／模型日志、场景截图与问卷是本次采集；参加过旧问卷不自动等于本次同意。不同意时关闭填写页面，不点击提交、不启动任务采集。问卷星拒绝跳转仍显示提交按钮，服务端保存行为未验证，不能承诺平台零保存。不要把自愿参加与成绩、同学关系或合作资格挂钩。
5. 在全流程问卷首页选择实验类型、填写研究者分配的编号。研究者另用本地 `questionnaire_unified.html` 的“研究者：关联记录”生成并下载不含回答的配置，用同一配置启动Unity。只有本地页面会生成 `study_session_id`，问卷星不会自动创建或读取它；研究者按参与者编号和阶段核对。参与者不用手填长编号，Unity不展示这些研究信息。
6. 每轮完成后暂停任务，回到同一份问卷的对应页。四轮分别填写第2至第5页，轮次间保持页面打开；页与选项不随机。没出现系统提问时，打断项按实际“没有被提问打断”选1；无法判断可选独立选项或跳过，不能当作4分。其他体验题也可跳过。
7. 最后自行填写第6页，再统一提交一次。回忆时只使用第1至第4轮，不加“快”“智能”“选择性”等描述。如果只完成部分轮次，不强迫比较四轮，也不替参与者补填。是否保留已有回答按已告知的退出安排及参与者意愿处理，记录实际已执行的轮次。
8. 如做追问，围绕具体事件：“当时发生了什么？”“你原本希望它怎么做？” 不要求参与者赞同系统，也不把研究者的解释写成原话。未经另行告知与同意，不采集人像、声音或桌面无关内容。
9. 每人结束后，核对一份合并答卷及对应会话日志。四轮评分在导出时展开为最多四条分轮记录，不能计为四名参与者。页面填写或提交不证明四轮任务均已执行；按日志核对，退出、跳过和技术中止保留实际分母。

## 共用设备的交接

所有到场参与者共用同一台手机或电脑。台式机验收确认全流程草稿的设备、IP、微信限答、断点续答、上次答案回填及总份数限制为关闭；独立账号一次限答控件未找到，不能标为已验证。新开预览为空白，公开入口的连续提交仍未测试。详见 [完成记录](desktop_completion.md)。

1. 正式收集前复核上述设置。获得发布及测试授权后，在同一个实际采集设备与浏览器上走完两次独立debug流程，核对第二次能进入空白问卷、前一人的回答不回填、两次记录分别保存。当前没有发布或提交授权，本轮仅登记此待验收项。
2. 同一人四轮之间保留页面，通过问卷的上一页／下一页继续，勿刷新或重新扫码。换人时关闭上一人的页面，再打开空白入口；核对参与者编号、实验类型、旧编号、选项和短答为空。本地入口点击“换下一位，清空全部”，并为下一人生成新的关联配置。
3. 配置只恢复编号，不能恢复已关闭页面的回答；不要将读取配置当作断点续答。交接设备前避免让下一位看到上一人的回答。
4. 原22人目标对应最多22份合并答卷，展开后最多88条分轮记录。预留2个预实验和20个正式槽位，实际数量可少；两阶段分开，缺失不补造，也不设置22份平台限额。

## 与旧问卷的关系

2026-10-18 核对的台式机旧聊天“录入问卷星问卷内容”显示，旧问卷 `Adjusting an AI Through Conversation`（问卷星编号 `384478976`）总计 22 份记录中有 19 份模拟回答和原有的 3 份。原有 3 份的来源尚未核实，不能直接称为真人回答。用户同日进一步说明部分人不能到场，本次实际人数未定；两处“22”不能视为同一批人。模拟或来源未核实的旧回答不计入真人结果，也不能作为群体需求的实证依据。

建立个人关联须先确认本次参加同意有效，并逐条核实旧回答的真实来源、本人当前的关联许可和已有匿名编号。Q7在撤回关联后虽隐藏，但前端仍保留旧值；不得因为Q7非空就关联。分析前必须检查Q3同意且Q6同意，许可缺失或已撤回时不使用该旧编号。服务端是否仍存有隐藏值未验证，不能把分析排除当作平台删除。不能用本次新分配的 P001 反推旧回答，也不能根据措辞或提交时间猜测身份。旧编号保存在限制访问的关联表中，不发送给 DeepSeek，不写进模型日志。问卷仍不收集姓名、电话或邮箱。

没有旧编号、不同意关联或旧回答来源未核实，都不影响参加本次实验；对应的旧回答不纳入关联分析。旧问卷题目本身可以说明设计背景，但旧 Q5 的假想偏好不能当作本次满意度或成功率的前测。即使旧回答被核实并完成关联，统计独立参与者人数时仍需去重。

## 导出、编码与分析

本地 JSON 保留 `answer_status`，区分 `answered`、`skipped`、`not_shown`、`cannot_judge`。问卷星导出先依据Q3筛选同意参加记录，旧关联必须同时满足Q6许可和来源核实；导出若有隐藏旧编号也不使用。随后对应这些作答状态；不要把空白转成 0，不把无法判断转成量尺中点。评分字段与现有 CSV 精确匹配：`interruption_1to7, control_1to7, effort_1to7, satisfaction_1to7`。

用冻结的 `participant_schedule.csv` 将正式 participant/block 映射到 condition。对每人四轮的评分做配对描述并计算差值；预先指定的 S 与 A 在打断评分上的差异单列，其余探索性结果注明。可展示各题分布、有效人数与参与者内区间；不把 80 份分轮回答当作 80 名独立参与者。问卷主观结果与实际成功、询问数、修复、等待和延迟分开报告。

本地导入示例（输入为实际回答文件，输出目录应是私有数据目录）：

```bash
python3 Docs/AppearanceExperiment/Study/survey/import_responses.py \
  --input-dir /path/to/actual/downloads \
  --schedule Docs/AppearanceExperiment/Study/materials/participant_schedule.csv \
  --out-dir /path/to/private/analysis
```

脚本接受本地合并JSON及旧分表JSON，不接受问卷星原始导出。首次获得实际导出后需核对列头、题号、选项编码和同意路径，再做可审计转换；不要把一行合并答卷算成六个人。实际回答、关联表和会话日志不要提交至公开仓库。
