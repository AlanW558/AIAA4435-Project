# 外形实验协议 v0.1

2026-10-18；预实验后冻结。研究问题：在同一个具身角色的外形定制系统里，可解释的选择性澄清，与直接执行、总是询问和原生 LLM gate 相比，怎样改变达成目标、打断与修复的权衡？本周完成该研究，后续语音实验独立报告。

## 1. 本次 22 位真实参与者的招募池

2026-10-18，用户确认本次另有 22 位真实参与者可以安排。先固定 2 个预实验槽位和 20 个正式槽位，预实验人员不进入正式效果分析。优先按可到场时段安排，不根据旧问卷偏好或实验表现选择正式样本。22 是招募池人数，实际到场、完成和退出人数另行记录。

同日核对台式机旧聊天“录入问卷星问卷内容”（记录编号 `01a09608-5657-7a91-9b79-e4c7220cd422`）：旧 AIAA4435 问卷 `Adjusting an AI Through Conversation`（问卷星编号 `384478976`）的最后记录显示，总计 22 份中有 19 份模拟回答，以及原有的 3 份。原有 3 份的真实来源尚未核实，不能称为已确认的真人回答。旧问卷的记录数不等于真实参与者数，也不能据此把本次招募池称为“同一批 22 人”。模拟和未核实来源的回答均不计入真人研究结果或群体需求结论。

课程目录中的 2026-09-12 问卷修订稿可以用作题目设计背景。该稿 Q4 至 Q11 以语音或行为为假想情境，不能直接证明用户需要某种外形设计，也不能作为外形实验的客观前测。Q5 是先问或先做的假想偏好；Q6 是等待区间，不能换算成实测平均秒数；Q1 不等于虚拟现实使用熟练度。

只有逐条核实某份旧回答来自真实参与者、取得本人同意关联，并核对已有匿名编号，才将该回答与本次记录对应。满足这些条件后，可把 Q1/Q5 用作描述性背景，探索原偏好与实际体验的关系。没有匿名编号、不同意关联或来源未核实，就不进行个人关联；模拟和未核实记录也不能转用于群体层面的实证比较。不能根据文本风格或提交时间猜测身份，也不能用本次新分配的编号反推旧回答。

正式实验使用新编号 `P001` 至 `P020`，姓名和联系方式不进入模型或分析表。主持时说明新增日志、截图及可选的旧回答关联用途，重新取得本次参与同意。若核实参与者此前接触过研究情境，记录这种接触并在报告中说明；不预设本次全部参与者都曾填写旧问卷。四个条件使用中性命名，不告诉参与者哪一个是研究者提出的策略。旧回答与新实验若有经核实的人员重合，统计人数时去重。

## 2. 系统与正式任务

一个固定角色、同一个固定 3D 房间、相同灯光/动画/观察位置。可以使用台式机运行更精细的模型和场景，但环境复杂度在四个条件中保持一致。本周三个可修改字段是外衣颜色、配饰（无/帽子/眼镜）、整体比例。比例围绕角色脚底缩放，不改变用户相机或世界比例。

正式任务分为四类，每类四个匹配变体，组成 A/B/C/D 四套。每人每个具体任务只见一次。

| 类型 | 目的 | 包含反例 |
|---|---|---|
| T1 明确修改 | 检查不必要的提问 | 明确覆盖旧软偏好也应允许直接执行 |
| T2 小幅模糊调整 | 检查可逆默认值是否足够 | 私有目标允许一个范围；不把“未给精确数值”自动标为必须询问 |
| T3 多种实质解释 | 检查有收益的澄清 | 私有视觉目标可能不在候选里，必须记录候选遗漏 |
| T4 历史/偏好 | 检查上下文相关判断 | 多个旧状态与唯一明确旧状态均出现；软偏好与硬锁区分 |

参与者看到目标效果卡、初始请求和需保持属性。模型只能看到公开的请求、当前状态、可见历史、已表达的软偏好与工具能力，不能看到目标卡、目标状态、类别标签或评分器。

主试次采用固定初始文本：参与者在头显中点击“发送这条请求”，后续澄清用同一个选项面板回答。这样第一周不需要 ASR，也避免 VR 键盘速度主导结果。它检验控制信息量下的澄清决策，不检验自然语音表达或自由提示能力。结束后可做一项自由输入定制，单独作定性材料，不混入主成功率。

目标卡在第一天用同一个 Unity renderer 生成截图，并附简短文字，确保颜色/配饰/比例可分辨。初始草案尚不包含真实角色截图；不应在截图和实际场景不一致时开始采集。

## 3. 四条件及原生对照

| 代码 | 运行规则 |
|---|---|
| E | 直接执行共同默认有效候选；允许之后检查和修复 |
| A | 每个初始请求询问一次；明确请求用确认，模糊请求用共同消歧问题 |
| N | 同一 DeepSeek 模型自主选择 ASK/ACT/UNRESOLVED；不提供选择性规则 |
| S | 根据冻结的 R1/R2/R3 和小步可逆例外决定；记录证据与命中规则 |

四组共用候选生成、候选排序、默认 patch、状态与历史、问题模板、选项数量、结果展示、撤销、修复上限、超时和等待提示。ACT 一律执行共同默认候选；ASK 一律呈现同一问题，不让 S 得到更精心的问题或更完整的上下文。技术校验、硬锁、不可实现的请求走共同出口，单独记录。

N 应命名为 **Native-gate / 原生 LLM 决策模块**。它处在共同 harness 内，并非完全自由运行的原生 agent。另做离线 Native-agent：同一基础模型获得原始上下文和工具，允许自行提出问题、形成 patch；它与四个 gate 的差异包含规划和问题内容，因此离线结果不能代替其真人 UX 对照。

共享 proposer 不接收 condition 字段。离线在同一输入上只生成一次候选，再复制给各 gate。正式试次各自调用同一冻结 proposer 并记录实际输出；跨参与者因 API 随机性而出现候选差异不能隐瞒。不要给 N 额外劣质提示词或故意削弱记忆；开发阶段给予 N 提示词和 S 阈值相同的预定开发机会。

记录 requested model、响应中的 model、请求时间、采样/thinking 配置、提示词哈希和调用量。DeepSeek 的模型别名可能更新；仅固定别名不等于不可变快照。将正式采集集中在两天，监测响应标识/公告变化；出现更新先暂停并记录版本事件，不能悄悄混为同一版本。所有费用和等待计入真实成本；不人为延迟规则条件来制造相同耗时。

## 4. 分配与一项试次

20 人采用四条 Williams 条件顺序，每条 5 人。条件×位置完全平衡，一阶有向条件转换各出现 5 次。任务集×位置也完全平衡；当前构造的条件×任务集为 4–6 人，属于近似平衡而非完全平衡。所有分配保存在 CSV；不得根据实时结果换顺序或任务。

1. 重置规定状态和对话，展示短历史；参与者阅读私有目标卡。
2. 参与者发送固定初始请求，开始记录端到端时间。
3. gate 做一次初始 ASK/ACT 决策；上限一次政策性澄清。没有可回答的问题时允许 UNRESOLVED。
4. 执行后立即保存首次状态、渲染值和角色截图，在任何修复之前判定首次提交是否正确。
5. 允许最多两次修复/局部撤销，四条件相同。研究者只提供标准操作说明，不能代用户解释意图。默认试次上限 120 秒，由预实验决定并冻结。
6. 用户点击完成后，三个固定的中性 tutor 文本回合检验外形持久性；这些回合不用 ASR/TTS，固定回复，不产生新的定制请求。验证阶段与用户完成时间分开。
7. 每 block 后用相同的自拟 1–7 分单项收集打断感、控制感、投入努力和满意度；最后简短访谈。

支持“其他/都不是/取消”回答，不能强迫用户从错误候选中选一个。如果使用自由文字修复，所有条件使用同一输入方式；第一天确认头显面板输入可用。手动调整作为共同恢复工具时要单列次数，不能把它记成模型正确执行。

## 5. 数据与分析

主要客观指标为 stable_goal_success：在共同时间和修复预算内，末态达到私有目标允许集合、需保持字段未发生最终误改，并在三个探针中保持。还必须检查实际 renderer 的材质/配饰/比例与状态相符，不能只比较 JSON。

同时报告 first_commit_success、过程中任意附带修改、问题数、修复/撤销数、未解决、超时、技术失败、候选遗漏、总体完成时间、模型等待和用户操作时间。完成时间包含失败/超时的预定处理，避免只比较成功任务的速度。总时间和去除已记录服务等待的交互时间分别报告，不重复减去重叠时段。

主比较是每人 S–N 的稳定成功比例差；S–A 的询问/打断差异、S–E 的首次成功差异为预定次要比较。对每个指标给参与者内差值与 95% 区间，按参与者整体 bootstrap（保留四条件和全部试次）；请求类型仅作探索性分析；旧 Q5 偏好相关性还须满足逐条核实真实来源、本人同意关联和已有匿名编号可对应这三项条件。若同时报告多项预定检验的 p 值，使用 Holm 校正；不显著不等于两策略等效。

20 人是可用资源下的探索性样本，不宣称已有充分功效。320 条 trial 不是 320 名独立参与者。问卷量表为自拟单项，不生成未经定义的总 UX 分数。系统故障保留在端到端指标中并另报；外部设备断连导致整场中止时，记录原因和已完成部分。预先规定到本周截止或 20 个正式槽位结束停止，不按显著性停止，也不把预实验数据事后补入正式样本。

旧问卷的题目可用于说明设计背景，模拟或来源未核实的回答不提供真人需求证据。新实验的结论限于实际完成研究的参与者、这组外形任务和所用模型及 harness 的初步比较。不能直接外推到语音交互、其他人群或所有虚拟现实角色。

## 6. 离线、冻结和实际完成标准

离线计划：24 个场景家族，每家族两个表述，共 48 个案例；每类 6 个家族。按家族分配每类 3/1/2 个到开发/验证/测试，总计 24/8/16 个案例。正式真人任务另行保留，不作为模型提示示例。这里的 48 是待制作规模，当前材料生成器只生成 16 张正式任务草案。

离线 E/A/N/S 和 Native-agent 使用同一冻结输入、隐藏目标及人工回答表；测试集 16×5=80 次策略运行。模拟器结果不替代真人数据。记录候选覆盖、错误 gate、问题无效和执行失败，防止把候选缺失归罪于策略。

冻结需包含构建与素材版本、Pico/XR/SDK、模型/提示词、policy.json、任务与私有答案、分配 CSV、日志 schema、超时/修复预算、排除和分析规则。结果文件必须来自实际运行，空白数据表不算实验完成。

中期材料应至少包含：可运行 VR 构建、版本清单、实际样本流程、四条件结果图、典型失败案例和适用范围。Selective 不占优也是完整结果；不能只演示人为选中的有利请求。
