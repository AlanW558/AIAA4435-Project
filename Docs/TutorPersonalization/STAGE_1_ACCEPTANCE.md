## 真实模型流程

按顺序完成下列流程，模型配置沿用本机。请求模型标识 `deepseek-v4-flash`，返回 `deepseek-flash`。本轮最多允许 18 次尝试，实际 15 次，均成功；禁用自动重试与备用密钥切换。

1. 从 Balanced 开始：要求之后仅关键点，同时提问 active recall，得到 Brief 实际回答。
2. 追问其作用，保持 Brief 并使用已有对话上下文。
3. 控件改 Detailed，再问同一知识问题，生成关键答案、理由及完整例子。
4. 控件改 Balanced，仍问同一问题，生成关键答案与理由。
5. 控件改 Detailed；要求“仅这一次用关键点”并提问，实际回答记录 Brief，持久设置仍为 Detailed。
6. 后续问如何应用于生物学习，自动恢复 Detailed。
7. 请求恢复最近一次滑块修改之前的长度，恢复 Balanced，其余字段保持。
8. 给出“仅关键点”与“更多解释及例子”两种竞争意图，S 提问，确认前保持 Balanced。
9. 从未来 STT 共用入口提供自然语言确认，进入 Brief；然后单项撤销恢复 Balanced，历史同步。

六次实际问答及最终状态保存在 `StudyData/macos/tutor-acceptance/live/unity-view.json`，右上角为 LIVE 的截图在同目录 `conversation.png`。调用记录和 ID 去重信息为 `server.json`，逐事件 JSONL 在 `logs/tutor/debug/`。这些均为工程证据，不是参与者数据。

已人工查看实际答案：三档在补充理由与完整例子上有区别，后续问题也能延续 active recall 的上下文。Brief 定义中仍出现“testing yourself or answering questions”这样的简短例子；这说明模型的关键点与补充说明边界并非绝对可靠。程序没有按字数/句数自动判定任务成功，也没有因结果符合预期就声称策略更优。最终用户研究仍由参与者评价是否达标。

## 故障注入与修复

验收专用服务在 localhost 8767 运行，使用明确 fixture，不读取密钥。故障接口仅存在于 `Backend/tests/unity_acceptance_server.py`，没有加入正式 `Backend/server.py`。

- **提交成功但丢失回复**：Unity 保留原请求体和 request_id，禁止新修改；Sync 可看到已提交状态，但仍保留恢复要求；Retry 原 ID 不产生第二条修改。
- **生成成功但返回错误格式**：不凭空补造答案；Sync 取回已完成问答；Retry 不再次生成或写入重复问答。服务端记录验证了重放 ID 相同。
- **忙碌期间的重复输入**：同一客户端不并发提交第二个控件操作或学习请求。
- **旧澄清确认**：另一个 HTTP 操作重置会话后，旧客户端选项被拒绝；不会覆盖重置后的状态。Sync 后恢复正常操作。
- **组件中断**：请求进行中禁用再启用客户端，保留未知结果，恢复后安全重放。
- **旧版本响应**：服务故意返回较早快照；客户端拒收，保留较新的设置与版本，下一次正常 Sync 恢复。
- **会话隔离与单次覆盖**：新会话没有旧问答和修改；单次长度只用于相应回答，后续仍按持久设置生成。
- **未支持的修改**：Voice 等尚未连接的请求保留状态，并显示未执行原因。

验收发现并修复两处反馈问题：Sync 后未知结果曾被显示为 Ready；UNRESOLVED 的后端原因曾被通用 Ready 提示遮盖。现在分别显示恢复提示或未执行原因；待生成的 job 也显示继续回复提示。

故意丢失 HTTP 响应会在 Unity Console 产生预期的 `Curl error 52: Empty reply from server`。默认后端未启动时会出现预期连接失败。检查中没有未处理的 C# 异常或编译错误；不要将这些故障注入日志算作正式环境的零错误声明。

## 复现

从仓库根目录运行。先停止占用 8765/8767 的旧调试服务，打开 Desktop Integration 场景。不要让不同模式的验收服务同时占用 8767。

免费故障验收：

```bash
Tools/AppearanceExperiment/.runtime/macos/bin/python Backend/tests/unity_acceptance_server.py
```

进入 Play mode，等待默认 8765 连接失败，再选择 `AIAA4435 > Tutor > Run Fault Acceptance (Play mode)`。最终 Console 显示 `PASS: 20 behavioral checks`，报告为 `StudyData/macos/tutor-acceptance/fixture/checks.txt`。

真实验收会消耗已有课程 API 额度。退出 Play mode，停止 fixture 后，使用本机已有 `.env`：

```bash
set -a
source .env
set +a
Tools/AppearanceExperiment/.runtime/macos/bin/python Backend/tests/unity_acceptance_server.py --live
```

再进入 Play mode，等待默认连接失败，选择 `Run Live Acceptance (Play mode)`。脚本按预期行为检查，遇到错误即停止，不自动隐藏失败或追加付费重试。模型输出可能导致不同的解释，重跑不保证仍为 15 次成功。报告路径为同级 `live/`，重复运行会更新报告，应先保存要保留的证据。

两种验收都使用临时 endpoint，退出 Play mode 后场景默认仍为 8765；终端 Ctrl+C 停止专用服务。验收组件在 `UNITY_EDITOR` 条件内，不进入设备构建，也未保存到场景。
