## 2. 各方向的解释与效果规则

| 方向 | 明确修改 | 定性或歧义要求 | 不应顺带发生的变化 |
| --- | --- | --- | --- |
| Speech rate | “90% of the default speed”→0.90；当前 1.20 时“reduce the current speed by 10%”→1.08 | “a little slower”使用公开当前值产生合理候选；未说清倍数基准时保留真实歧义，不默认当作当前值 | 不缩短答案，不换 Voice/Tone；不把倍数解释为实际音频时长保证 |
| Reply length | Brief＝关键答案；Balanced＝关键答案＋短理由；Detailed＝关键答案＋较充分解释＋适用的例子/步骤 | “remove the example but keep the reason”→Balanced；“more support”可能涉及内容或鼓励风格 | 不通过加速制造“更短”，不将固定字数视为已支持能力 |
| Tone | Professional＝专业、克制、直接；Friendly＝温暖友好；Encouraging＝支持尝试、鼓励进步 | “warmer wording”可指 Friendly；整体“calmer”可能涉及语速或声音，不能机械映射成 Tone | 不增加无关夸赞，不自动增加解释，不改变 Voice 或 rate；三个风格不是强度等级 |
| Voice | “Use Voice B”→voice_b；唯一历史声音可以恢复 | 音色描述必须来自已核验的实际声音能力；当前只有占位时，相关描述标为未具备依据 | 不把“friendly voice”直接等同 Friendly 措辞，也不自动改语速 |
| Appearance | 按已支持字段修改；例如绿色西装、用帽子替换眼镜 | “more casual”可对应服装或配饰等不同结果；候选只来自已具备资源 | 不把“more professional”一概当作换服装；保留要求涉及的其他设置不变 |

Reply length 的组成规则不能删除问题本身要求的信息：用户问“为什么”时，直接原因就是关键答案；明确请求例子时，例子可能是回答核心。阶段二真实调用中，Brief 偶尔仍带解释性内容；本阶段继续检查，但不把结构化输出成功当作参与者目标已达成。

### 语速计算与精度（新增实施约定）

1. `1.00` 表示当前所选声音下模型的默认速度；切换 Voice 时保留 rate 倍数，不承诺不同声音在 1.00 时具有相同实际语速。
2. 模型识别操作、数值和基准，程序执行计算。首次请求中的“当前”使用四分支共同起点；展示后修复中的“当前”使用该分支请求时的状态快照；等待或重试不重新取一个变化后的值计算。
3. 区分绝对倍率、乘法比例和倍率差值。例如当前 1.20：设为默认的 0.90 倍→0.90；降低当前速度 10%→1.08；倍率减少 0.10→1.10。
4. 当前存储精度为 0.01。直接输入或计算结果若不在可表示网格上，不静默四舍五入；例如 1.15×0.95＝1.0925，应说明精度限制并让用户另选可支持值。越界同样不静默截断。普通浮点表示误差不属于用户要求的精度变化。
5. 尚未绑定 TTS 时，只能确认设置值已更新；不能声称音频已变慢、已试听或已经达标。后续提供商能力不符时要显式处理，不能暗中更改此契约。

## 3. 作用域、保持、默认与恢复

以下是阶段三实施约定；除 Reply length 已有的一次回答机制与底层状态操作外，其余仍需接线。

| 操作 | 约定 | 边界 |
| --- | --- | --- |
| 普通持续修改 | 只对当前策略分支持续生效，直到后续修改或本题结束 | 实验中不自动带入下一题，不改其他策略 |
| “this answer only” | 四项对话属性可形成下一次回答专用设置快照；持久设置不变 | Reply length 已有基础；其他属性待扩展。重试和重播使用原快照，不消耗第二次；Play sample 不消耗它 |
| “for this task” | 当前题内持续生效，不等同只对下一句生效 | 不自动生成跨题个人偏好 |
| 外观临时生效 | 本阶段按当前题/分支持续修改 | 不新增“播放时换外观、播完自动还原”；明确要求此能力时说明尚不支持 |
| 多属性请求 | 同一个候选包含完整修改及保持约束；校验通过后原子提交 | 任一部分不受支持或相互冲突，不执行受支持的子集后宣称整个请求完成 |
| 恢复默认 | 恢复用户指定字段的应用默认；语速默认＝1.00 | 不等于本题起点，不等于上一个值；“全部默认”必须明确范围（外观/对话/全部设置） |
| 恢复本题起点 | 从共同 baseline 恢复指定字段 | 本题起点由 task_start_settings 单独保存（公开 setup 后捕获）；可能是 1.20，不能用默认 1.00 代替；不删除历史和首次结果 |
| 撤销上次修改 | 回退指定字段最近可撤销的改变，或最近一次完整修改 | `undo all` 的已有含义是最近一次可撤销修改，不是清空整个会话；局部撤销不覆盖无关新设置 |
| 恢复历史目标 | 从提供的公开历史选定旧值，只恢复要求的字段 | 唯一引用直接形成一个候选；多个真实可能目标保留歧义；历史缺失不编造 |
| 保持其他设置 | 没有请求改变的字段保持当前值，显式保持优先约束候选 | 整体角色替换按第 1 节展开；不能靠“默认补全”破坏保持要求 |
| 无变化请求 | 目标等于当前状态时允许明确告知无需更改 | 不制造虚假的 changed 记录；A 对有效的新定制请求仍按其策略确认 |

临时设置需要分别显示“持续设置”与“这次输出实际使用设置”，不能让界面将两者混为一谈。若一次请求同时要求某字段临时、另一字段持续，当前解释结构仅有单个 scope；本阶段先明确报告无法用当前请求结构执行，并邀请拆开表达，不擅自改成全部持续或全部临时。

已有底层撤销在恢复后组合非法时会整体拒绝；外观恢复继续遵守这一点，不额外自动换装。语音/文本提出恢复需求属于新自然语言定制请求；点击明确的撤销控件属于直接操作，两者不要重复走同一套确认。

## 4. 四策略共同契约与 Selective 扩展边界

共同流程：一次公开初始请求 → 一次共同解释 → 1–3 个有效候选及共同默认 → 四个决策模块 → 分支独立澄清/执行 → 全部准备好后首次统一展示。候选在进策略前完成数值计算、外观展开与完整状态校验。

| 模块 | 继续采用的规则 | 本阶段需补齐 |
| --- | --- | --- |
| E | 执行共同默认有效候选 | 允许五方向完整候选；非法/不受支持仍为 unresolved，不强行执行 |
| A | 有效新定制请求先确认/澄清；回答已有问题不再反复确认 | 问题、选项能准确说明属性、作用域及真实影响；不能继续只显示 reply structure |
| N | 同一基础模型基于共同公开信息决定 ACT/ASK/UNRESOLVED | 能读取五方向能力；不获得研究私有目标、S 规则或额外历史 |
| S：R1 | 未解决的历史/指代且有多个可区分候选时 ASK；没有可用依据时 unresolved | 扩展至所有字段，唯一历史引用不凭空增加问题 |
| S：R2 | 可能覆盖已提供的软偏好、且用户没有明确授权覆盖时 ASK | 从 reply_length 专用判断扩展至相关字段；明确“虽然通常 X，这次 Y”可覆盖旧软偏好 |
| S：R3 | 候选造成不同实质结果时 ASK | 比较完整结果和实际改变字段，覆盖分类选项差异及跨属性解释；不是所有数值差异都自动视为实质差异 |
| 直接控件 | 四策略共享；明确选择不再过语言策略 | Speech rate、Tone、Voice 控件接通；阶段锁定规则四策略一致 |

旧外观 S 已有“小幅可逆”规则：仅比例调整、默认变化不超过 0.05 且候选跨度不超过 0.05 时可 ACT；比例候选跨度达到 0.10、分类结果或修改字段不同会触发 R3。R1/R2 优先于这条小幅规则。迁移时保留现有规则依据，并回归已有外观案例，不因统一框架悄悄改写旧策略。

**语速的数值阈值尚未由旧代码或实验确认。** 第二步的实施建议是先用“默认变化≤0.05、候选跨度≤0.05”作为小幅可逆的工程起点，其他多目标数值差异保守询问；须作为新规则单独版本化和测试。它不是已经验证的感知阈值，也不能从参与者私有目标范围反推候选。Tone、Voice、Reply length 为离散选择，不使用“小一点＝下一档”的统一数值规则。

所有待澄清问题解决前，仅显示共同起点、问题与中性进度；隐藏新属性、外观、回答、历史和声音。故障需重试或明确结束为未完成。首次快照固定，后续修复只更新相应分支及其评价版本。

## 6. 面板、对话历史与试听边界

- 保留 **Adaptive Conversational Agent**、Conversation / Controls / History 三页、英文内容及现有半透明/轻微发光风格。
- Controls 的四项属性为主内容；Appearance 不增加独立页或编辑面板，结果摘要和属性修改共同进入 History。
- Conversation 保存实际问答；History 保存修改前后、来源、作用域和撤销关系。示例历史与参与者真实操作区分，失败生成不伪装成完成对话。
- 当前解释上下文最多使用最近 20 条修改、6 次完成对话；生成使用最近 6 次完成对话。这不是完整长期记忆承诺。引用超出可用上下文时不可编造，后续若扩展检索需单独实现。
- Tone 必须进入回答生成上下文及对应复用判定；不同 Tone 不能误复用旧答案。Voice/rate 主要影响未来语音输出，同一文字并不代表同一声音结果；音频缓存将需要模型、声音、速率及受支持风格等标识。
- Play sample 保留短句左侧、按钮右侧的紧凑布局。语音阶段前按钮保持不可播放状态；未来与正式回答共用语音路径，一次只播放一个分支，切换或改变相关设置停止旧播放。
- 固定文字可比较 rate/voice；不能展示 Reply length，也不能完整展示基于措辞的 Tone。固定例句的可听风格需由 TTS 能力支持；Tone 实验仍需实际生成回答。研究中的 rate/voice 同题试听使用相同文字，不用不同文案混入比较。
- 任务完成由参与者问卷判断，不通过字段设置成功、播放完成或 Next question 自动标为成功。问卷语音不保存，仅保存需要且确认的 STT 文本。

## 7. 实施顺序与第一步交付检查
