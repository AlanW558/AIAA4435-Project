## 连续流程与真实观察

第一题公共起点为 rate=1.20，其余使用默认。一次请求同时要求“当前语速降低 10%”、Voice B、Friendly、Brief，并询问 active recall。真实四分支均得到 1.08 / Voice B / Friendly / Brief；A 等待澄清时结果隐藏，暂停/恢复保持屏障，答复后才统一开放。各分支生成结果与设置快照关联。

随后仅修复 E：

1. 要求“默认速度的 90%”，得到 0.90，区别于先前相对当前速度计算的 1.08。
2. 改绿色运动服，再只改紫色，最后引用“紫色之前的颜色”恢复绿色；对话设置、眼镜、比例和身份保持。
3. 一次回答专用 Encouraging＋Detailed，回答使用临时快照；下一次问题回到持久的 Friendly＋Brief。A/N/S 状态与首次快照不变。
4. 要求恢复任务起点：初次真实模型错误选 1.00，触发停止；修复后在精确重建的公开前缀上复测，恢复正确的 1.20，再按字段撤销到 0.90。
5. 要求速度 2.00 与 Voice C 必须一起改变，复测返回 unresolved，两个字段均未部分执行。

第二个真实复测案例提出“更平静”可能表示更慢语速或更专业中性的措辞，明确两者是替代解释。A/S 均澄清；N 实际也选择澄清。各分支准备完成前不揭示。A/N 选择 Professional、保持 1.20；E/S 选择 1.08、保持 Friendly；Voice B、回答结构和外观均保持。不同分支的确认不被复制。最终直接退出，没有伪造问卷提交。

真实运行的工程反馈统一为 `unable_to_judge` 并标注 synthetic，使用现有 Q1–Q7 API 仅验证版本关联。它不是参与者评价，不意味着重新确认旧六维问卷。完整提交/新题行为由修复后固定模型流程和 Unity 回归验证；首次真实运行只保存过合成反馈，因失败而未提交。

## 发现与修复：任务起点不等于默认

原模型上下文有当前设置和最近修改历史，但没有独立的任务起点。尽管最早修改的 before 值是 1.20，模型仍把“任务开始值”解释为默认 1.00。

修复：

- `TutorState` 单独保存 `task_start_settings`，创建时复制初始值；clone、提交和撤销不更改它。快照返回副本。
- 比较任务在公开演示 setup 完成后捕获起点，四分支共享；新题重新捕获自己的起点。单会话 reset 同样建立新起点。
- 解释上下文显式提供该公共快照，提示区分 task_start_settings、当前 settings 和 capabilities.defaults；旧快照没有该字段时为未知，不自动补成默认。
- 起点不会随最近 20 条修改历史的截断而丢失；不扩大其它历史的窗口，也不宣称无限对话记忆。

版本更新：状态 `tutor-state-v2`、解释 `tutor-interpretation-v4`、比较执行 `tutor-comparison-execution-v6`。策略仍为 `tutor-gates-v2`，文字生成仍为 `tutor-answer-v4`。客户端忽略新增快照字段，桌面回归通过。

这是明确上下文和提示后的实际案例修复，不是对所有自然语言引用正确率的保证。模型仍可能误解未覆盖的措辞，后续须保留用户修复入口和分析证据。
