## 1. 研究结构与数量

| 模块类型 | 内容 | 条件 | 反馈单位 | 核心字段 |

| attribute_comparison | 四属性，各四情境×两题，共 32 题 | E/A/N/S，同一初始语音文本与公共起点 | 每题每策略一次，共 128 份 | completion＋四项评分 |

旧独立十二道外观题不施测；旧 60 题、旧六评分、五次方向偏好不恢复。第一次外观研究单独报告，本次自然情境只支持 S 连续体验的评价和问题分析，不构成策略优劣的横向证据。

## 2. 外层流程及放行条件

以下为逻辑状态，不要求立刻按相同名称创建全部 API。

| 状态 | 参与者活动 | 正常继续的条件 | 需保留的状态 |
| --- | --- | --- | --- |
| familiarization | 学习语音、试听、调整、切换结果和问卷操作 | 熟悉流程完成；练习不纳入正式数据 | practice 标识，实际完成范围 |
| attribute_task | 阅读任务卡、检查指定起点、自然表达、回答澄清、比较/修复 | 四分支当前评价完整且服务端确认提交 | task ID、版本、初次揭示和最终结果、每策略反馈 |
| attribute_preference | 完成该属性八题后选偏好 | 有效偏好保存成功 | 对应八题及实际体验范围 |
| comparison_overall_preference | 完成四属性和四次偏好后选总体偏好 | 总体偏好保存成功 | 范围仅四属性，不含自然情境 |
| natural_intro | 休息、阅读开放引导；创建独立 S 会话 | 新会话和起点加载成功，参与者开始 | 独立 session ID、起点、模块顺序 |
| natural_active | 自由交流；随时修改交流属性/外观 | 达到预先确定的结束规则并选择进入反馈 | 连续历史、修改、澄清、修复、实际尝试范围 |
| natural_feedback | 对本段整体填写分类＋五评分 | 当前评价完整且服务端确认提交 | 固定评价范围及会话最终状态 |
| study_complete | VR 实验完成，可进行访谈 | 访谈不是完成条件 | 完成/退出/技术中断分别记录 |

- 四属性内部顺序待定，记录实际顺序；自然情境在总体比较偏好之后。
- 四属性统一揭示屏障继续保留；S 自然情境不创建其他分支，不等待并不存在的策略。
- 正式任务按任务库加载起点及公开历史，准备界面允许检查/试听，不允许随意改写任务基线。自由准备属于练习/熟悉阶段。
- 自然情境重置 tutor 历史、偏好和设置，但不删除此前研究数据；段内不再逐题清空。学习效应仍存在，不能声称初次使用。
- 自然情境不强制逐一修改全部属性或先修改属性后改外观；未体验的能力不计为失败或成功。
- 暂停、退出始终可用，不要求先填完问卷；缺失、退出和技术错误不可自动补为 Unable to judge。进入下一题和成功达标是两个概念。
- 结束自然交流时，未完成请求须明确解决或停止并记录，再固定评价范围。若返回交流并改变所评价过程/结果，旧问卷须失效或要求重新确认，不能混入迟到结果。
- 保存和推进分开：收到保存确认后才进入后继状态；未知网络结果用原请求 ID 重试，不重复建立题目/偏好/会话。

## 3. 三种目标问卷版本

| 用途 | 目标版本值 | 现状 |
| --- | --- | --- |
| 四属性逐策略反馈 | attribute-feedback-v2 | 新增；替代新实验中的旧 task-feedback-q1-q7-v1 |
| S 自然情境反馈 | natural-selective-feedback-v1 | 新增独立类型，不借用四策略任务反馈 |
| 属性/总体偏好 | strategy-preference-v1 | 新增，scope 区分 attribute / comparison_overall |

旧 task-feedback-q1-q7-v1 继续明确标为历史工程格式；不重标为新版，不按题号删除两项后假装语义一致。旧 q2–q7 不做自动回填/转换。新版拒绝混入旧字段或其他问卷类型的字段。模拟答案与真实参与者数据必须区分。

### 3.1 四属性逐策略反馈

| 字段 | 类型/允许值 | 要求及说明 |
| --- | --- | --- |
| completion | fully_met / partly_met / not_met / unable_to_judge | 必答分类；题干见主设计 6.1；不是等距分数 |
| ratings.effort_ease | 整数 1–7 或 unable_to_judge | 必答；交互省力程度，高分积极 |
| ratings.control | 同上 | 必答；修改控制感，高分积极 |
| ratings.clarification_appropriateness | 同上 | 必答；是否询问的决策合适程度，高分积极 |
| ratings.satisfaction | 同上 | 必答；本任务整体体验满意度，高分积极 |
| reasons | 去重的原因代码数组，允许空 | 可选；只在 completion 非 fully_met 时适用 |
| comment | 已确认 STT 文本，允许空 | 可选，所有 completion 均可填写，包括 fully_met |
| comment_confirmed | 布尔 | 非空 comment 必须为 true；未确认文本不能提交 |

原因代码沿用 target_mismatch / unwanted_change / not_maintained / hard_to_verify / interaction_problem / other。not_maintained 仅在确实发生后续交流时适用；改选 fully_met 时移除不再适用的原因，但不自动删除通用备注。

结果未达标仍允许作答和正常提交。技术异常由系统另记，不能代替参与者选择 completion。更新分支交互/结果后，该分支旧评价不应仍算当前完整；保留草稿但明确要求重新确认。

### 3.2 S 自然情境反馈

| 字段 | 类型/允许值 | 要求及说明 |
| --- | --- | --- |
| goal_fit | fully_met / partly_met / not_met / unable_to_judge | 必答；个人目标符合程度，不是受控任务 completion |
| ratings.effort_ease | 整数 1–7 或 unable_to_judge | 必答；整段个性化交互省力程度 |
| ratings.control | 同上 | 必答；整段修改控制感 |
| ratings.clarification_appropriateness | 同上 | 必答；整段澄清决策合适程度 |
| ratings.satisfaction | 同上 | 必答；整段定制体验满意度 |
| ratings.interruption | 同上 | 必答；高分表示更多打断，与前四项方向不同 |
| comment / comment_confirmed | 同四属性 | 可选；提示回忆一次帮助或打断交流的事件 |

英文题干见主设计 11.4。此版无额外必答原因题，也不直接复用受控任务的原因数组。与四属性有同名维度不代表同一题干或同一测量单位，导出必须保留类型和版本，不能直接混算。没有问过澄清也可评价“是否询问”的决策；未能体验或判断时可显式选择 Unable to judge。

### 3.3 策略偏好

| 字段 | 类型/允许值 | 校验 |
| --- | --- | --- |
| scope | attribute / comparison_overall | 总体指四属性比较，不含 S 自然情境 |
| domain | speech_rate / reply_length / tone / voice；总体时为空 | 与 scope 对应 |
| choice_kind | selected / no_clear_preference / none_acceptable / unable_to_compare | 必答，无默认值 |
| selected_conditions | E/A/N/S 的去重集合 | selected 时 1–3 个；其他种类必须为空 |
| comment / comment_confirmed | 已确认 STT 文本与布尔 | 可选，不作为继续条件 |

用户选四者无差别时使用 no_clear_preference。允许并列但不将同一人自动计为多个独立参与者；偏好不从评分推算。不存在 natural_scenario 偏好记录。

### 3.4 统一评分与完整性

- 锚点：1 Strongly disagree；2 Disagree；3 Somewhat disagree；4 Neither agree nor disagree；5 Somewhat agree；6 Agree；7 Strongly agree。
- Unable to judge 是独立显式值，不等于 4、0、缺失或失败。缺少字段表示尚未作答；不默认填中点。
- 草稿允许不完整；提交要求该版本的全部必答字段，拒绝越界数字、布尔冒充整数、额外评分字段和无效枚举。
- 不预设总分，不自动反向转换 interruption 后合成量表；条目为项目自拟/改写，不宣称标准量表。
- 四属性提交要求 E/A/N/S 四份当前有效反馈；自然情境仅需一份 S 会话反馈；偏好按其独立规则提交。

## 4. 数据关联与保存边界

以下是需要覆盖的逻辑字段。现有 task_id、series_id、branch_revision 等继续复用；新研究外层字段在接入时明确映射，避免将 tutor session_id 与整场研究编号混用。

| 关联层 | 目标字段/内容 | 目的 |
| --- | --- | --- |
| 研究运行 | study_run_id、participant_id（匿名编号）、protocol_version、run_kind（practice / engineering / study）、prior_participation | 关联整场实验、区分练习/工程/研究，记录旧参与者 |
| 模块 | module_type、module_instance_id、domain、实际 module_order | 区分比较与单策略自然情境，不只靠自然情境方向字符串 |
| 受控任务 | task_id、task_code、scenario、series_id、sequence_index、previous_task_id、task_manifest_version | 关联选定 32 题及实际执行顺序 |
| 策略评价 | condition、branch_revision、首次揭示快照、最终评价快照、feedback_revision | 评分针对哪一策略、哪次过程/结果 |
| 自然会话 | session_id、condition=S、initial_state、final_state、evaluation_revision、实际交互事件范围、结束原因 | 固定被评价的连续过程，保留未完成请求与实际能力使用 |
| 问卷 | questionnaire_version、answers、submission_id、保存时间、draft/submitted 状态 | 版本化、去重、缺失与提交分开 |
| 偏好 | scope、关联 module_instance_id 或已比较模块列表、实际体验范围 | 不把没有体验过的内容当作偏好依据 |
| 异常 | 退出、暂停、技术中断、重试和恢复记录 | 不填造完成数据；具体事件编码在实现时与现有日志映射 |

- 服务端校验身份/版本关系，研究元数据由可信流程提供，不由参与者手输或模型推测。
- 默认记录实际提交的参与者 STT 文本、tutor 输出、澄清与修复；不保存参与者原始音频。播放事件说明播放过程，不证明参与者已听懂。
- 问卷/偏好/访谈文字独立保存；即使复用 STT 服务，也不能进入 tutor 历史、请求解释或策略决策。
- 问卷 STT 需绑定当前问卷、策略/会话及字段；切题、切策略或过期响应不得误写到新问卷。允许重新口述、确认或放弃，不强制手柄打字。
- 保存原始分类与评分，不凭日志改写参与者答案。日志用于核对与解释，研究分析中的排除/缺失规则另行确定。

## 6. 下一步实现的验收清单

1. 四属性每策略只要求分类＋四评分；旧六评分不得混入新版，interruption 不出现在属性问卷。
2. 四分支结果/过程变化使对应旧反馈失效；重看/重听本身不清空已填答案。保存确认前不推进。
3. Unable to judge 可有效提交；缺答、默认值和系统自动填答不可用于放行。
4. 属性末仅一份偏好，总体偏好仅在四属性结束后一次；没有第五个方向偏好。
5. 问卷口述文本正确绑定、需确认、不保存原始音频、不进入 tutor；切换或迟到响应不污染其他答案。
6. 自然问卷接受 goal_fit＋五评分且仅对应 S 会话；不要求四分支或受控任务 completion。
7. 偏好集合/特殊选项互斥；重试不重复提交；问卷与日志可通过匿名研究编号和任务/会话版本追溯。
8. 工程模拟数据明确标记；旧工程记录保持旧版，不生成貌似真实的新研究答案。

## 7. 尚待确定但不阻塞新版问卷基础实现

- 可选访谈五题改写，尤其旧“假设只用一种策略”的问题；五选二及不按评分挑题的原则保持。
- 招募数量、分析主次、缺失/排除规则、实际实验时长与试运行调整。现有核心选择量仍较大，后续依据实际时长决定是否采用原先讨论的任务分配方案，不在此步擅自减题。
