## 本次实现

- 开始前显示英文任务卡：目标说明、自由口述提示和练习标识；点击 `Start task` 才创建对应任务并进入共享准备。
- 面板底部显示方向与 `Task x/y`；保留 Conversation / Controls / History 三个主页签和现有暖色半透明风格。
- `Task` 按钮可重看当前任务。任务卡打开时隐藏下层页面，阻止录音、试听、发送和属性调整；关闭后保留同一任务及澄清问题。此时不把被遮住的结果计作页面展示。
- `Next task` 依赖后端 `can_submit`：四个策略的当前结果都要有完整反馈。结果修改导致反馈过期时，按钮重新锁定。
- 下一题先提交本题，再调用既有 `/next`，只有确认新 task ID、previous task ID、series ID、sequence index 和题目元数据都匹配后才推进进度。
- 新题先显示自己的任务说明，再进入自己的共享准备。不会自动把任务目标当作参与者发言，也不继承上一题的对话或结果。
- 最后一题按钮显示 `Submit feedback`。提交后明确停在方向偏好反馈等待页面，没有自动补偏好、跳到下一方向或宣称全部实验结束。

## 任务内容与研究边界

默认资源为 `Assets/Project/Resources/Tutor/PracticeTaskSequence.json`，包含同一 Reply length 方向的两道**练习任务**，用于验证导航，不是正式题库。此次未将旧 60 题或旧外观方向恢复为最终方案。

当前任务清单格式仅接受 `purpose: practice`，不允许把它改成 formal 后直接开始采集。方向可配置为 speech_rate、reply_length、tone、voice、natural_scenario；后端新增 natural_scenario 元数据值，同时保留 appearance 兼容旧工程测试。支持该元数据不等于自然情境任务已经设计完成。

研究规划仍为四属性 × 四情境 × 两题 = 32 题，加模拟自然情境。正式任务数、模块划分、历史/偏好情境所需公共上下文和最终问卷均需之后确认。当前练习清单不包含 C4 历史准备素材；本次不声称完整研究任务可执行。

当前导航可在一个方向内逐题推进；跨方向转移有意停在偏好环节，等待下一步接入偏好记录后再放行。所有方向与任务数由清单定义，不在 UI 写死为 60 或 32。

## 本地任务说明与模型输入隔离

清单保存模块方向/标题，以及每题 task_code、scenario、title、instructions。任务标题和 instructions 仅用于参与者面板。

客户端使用单独的 `TutorTaskStart` 传输类型，只发送 task_code、domain、scenario，再由比较客户端加入既有请求 ID、debug 身份和 require_preparation。不会直接序列化整个任务卡。用户的实际 STT/提交文字仍是模型接收任务意图的来源。

后端继续拒绝 comparison 创建请求中的 instructions 等额外字段。导航练习期间没有创建真实参与者编号或更改 debug 数据路径。

## 反馈与异常处理

本次没有问卷输入界面，也没有默认填写答案。正常手动操作目前会在结果比较之后等待反馈，不能绕过这一门槛。联调脚本通过已有 SaveFeedback 接口写入明确标记的工程测试答案，不能作为真人实验数据。

创建、提交、换题响应丢失时，保留现有请求 ID，通过 Retry 恢复；不乐观增加题号。已知的提交/换题拒绝不会偷偷重试产生新任务。身份无法核对则停止推进并提示研究者处理。结束未提交任务不会算作完成，也不会自动跳题。

本次未新增跨编辑器/后端重启的实验恢复机制：当前后端任务实例仍驻留内存。已有持久日志及播放补传不代表整个任务流程可在重启后恢复。正式采集前需单独处理实验恢复及参与者会话登记。
