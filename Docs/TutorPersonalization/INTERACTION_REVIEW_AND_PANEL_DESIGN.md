## 从实际画面发现的改进点

1. 面板主要显示最后一条状态，缺少持续可见的当前属性和值；未来应显示当前语速/回复长度/语气/声音，外观页显示角色和相关属性。
2. 底部“全部/颜色/配饰/大小/形象/服装”实际上选择撤销范围，标签容易被理解为修改分类。改用“修改记录→仅恢复此项”，明确恢复前后值。
3. 只有最新请求/反馈，没有可查阅的对话上下文。对话记录与属性变更记录应分开，前者服务交流，后者服务解释与恢复。
4. 澄清已有取消与补充说明；新面板应继续支持这些出口，等待澄清期间不提交其他可能冲突的设置。
5. “完成修改”适合原外观实验任务，却不应终止每次导师对话。新主界面使用持续会话，设置变化后回到对话。
6. 斜置面板中辅助文字在桌面截图较小。可增大字体、减少常驻内容；最终空间尺寸及位置需戴头显验证，不能只凭截图定规格。

## 新面板方案（设计阶段）

保留现有暖色场景和青绿色操作色，单个世界空间面板按页呈现。默认进入对话页；统一处理连接中、生成中、待澄清、播放中和错误状态。

- **对话**：本次对话记录、当前回答、文本输入；后续接入语音输入和停止播放。澄清直接在当前请求附近出现，候选解释/取消/重新描述齐全。
- **说话方式**：speech rate、reply length、tone、voice；编辑是草稿，点“应用”后生效，失败保留草稿和已生效值。首版作用域限定本次会话。
- **外观**：复用现有角色/衣服/颜色/配饰/比例能力与渲染器；根据角色能力显示有效选项，切换角色前说明必要的默认外观联动。
- **修改记录**：按次记录来源、属性前后值、时间、生效范围和状态；默认只撤销选定属性最新有效变更，保留其他属性。若同属性已被再次修改，先处理最新变更或明确确认历史恢复。
- **常驻摘要**：当前已生效的说话方式。与编辑中的草稿明确区分；状态变化不只依赖颜色。

对话历史包含 user/assistant 消息；修改记录包含结构化操作。二者都关联 session_id 和 request_id，但不能将后端事件日志直接当作适合展示或送入模型的对话历史。

交互预览是独立设计演示，包含明确请求、歧义澄清、取消、按属性恢复、设置草稿与应用；没有接入模型或声音。声音 A/B/C 是占位，不代表已经选定供应商。0.7–1.3× 是设计范围，实际能力和听感需接入语音服务后确定。外观预览仅示意部分控件，实际实现需保留完整能力表。

## 下一步实现顺序和验收

1. **定义共享会话状态和接口**：将说话设置、外观状态、对话消息、变更记录分开；明确 revision、request_id、pending clarification、错误重试和取消语义。按钮设置和自然语言修改走同一校验/提交入口，避免各存一套状态。
2. **先接文本对话与 reply length / tone**：沿用现有配置中的 DeepSeek 模型；把偏好注入对话生成，保留上下文。长度先定义可测的短/中/长目标，不把 max_tokens 截断直接等同于回复长度控制。验收多轮对话中偏好延续，修改不丢上下文。
3. **接入 TTS 后实现 speech rate / voice**：语速作用于实际音频；voice 是可用声音标识；tone 是表达方式，两者分离。用同一句试听验证速度、音色、停止播放和切换行为。提供适配层，避免将语音供应商/模型写死在面板里。
4. **扩展 Selective 与历史恢复**：先按属性明确候选差异和安全默认，再复用策略结构。外观的数值阈值不能直接移植为语速/长度阈值。“刚才那种声音”“慢一点”“更自然”等需有可追溯参照。验收明确请求直接执行、歧义时状态保持、取消不变、局部恢复不覆盖其他修改。
5. **落入新 Unity 场景/面板并完整验收**：先桌面复现设计流程，再 PICO 检查射线、键盘、显示距离、遮挡和音频。最后补会话存取、加载失败提示与可导出的调试记录。会话恢复后显示真实已生效设置，避免只恢复视觉选项。

首版优先“对话+四项设置+澄清+会话内历史”。跨会话长期记忆、自动推断偏好、更多模型选择、多作用域设置可以后续再加，不作为这轮必需项。模型选择保留在后端配置/研究者配置中，普通用户只选择他们能理解的交互效果。

本次没有修改运行时交互脚本或保存场景变化，也没有改动已完成研究的材料。后续新功能使用独立能力版本和新场景/面板，保留现有 study-v1 结果的可追溯性。
